03 — LangGraph Nodes
1
Input Guardrail
Uses Gemini to classify intent into SCHEMA_INFO, DATA_QUERY, or HARMFUL. Blocks DDL operations before reaching LLM. Returns dynamic schema info from Qdrant when user asks about available tables.
intent classification DDL blocking Gemini Qdrant scroll
2
Schema Retrieval
Embeds user query using Gemini embedding model (3072 dims). Searches Qdrant using cosine similarity. Returns top-2 relevant tables with db_type — this determines which database to route to.
RAG cosine similarity Qdrant query_points db routing
3
Relevance Check
Asks Gemini YES/NO — is this query answerable with retrieved tables? Prevents wrong table matches. Without this, "show students" would try to query customers table.
yes/no classification Gemini hallucination prevention
4
SQL Generation
Builds a structured few-shot prompt with role, rules, schema, custom formulas (revenue = quantity * unit_price * (1-discount_rate)), and 4 examples. Sends to Gemini. Cleans markdown backticks from response.
few-shot prompting Gemini LLM multi-DB dialect MQL support
5
SQL Validation
Independent second guardrail. Checks query starts with SELECT. Uses regex word boundaries to block DROP, DELETE, TRUNCATE, ALTER — without false positives on column names like deleted_at.
defense in depth regex SELECT enforcement
6
Execution
Routes by db_type from state. PostgreSQL via psycopg2, MySQL via pymysql, MongoDB parses LLM JSON then calls collection.find(). Returns standard {columns, rows} format for all databases.
db routing psycopg2 pymysql pymongo Langfuse tracking
